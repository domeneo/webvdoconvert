### 3. ข้อค้นพบสำคัญทางเทคนิค

1. **ทำไมไม่แนะนำให้ใช้โหมด QP คุมบิตเรต:**
   - โหมด QP จะพยายามรักษาพิกเซลรวมถึง Noise ไว้อย่างตายตัว เมื่อเจอฉากยาก (น้ำกระเด็น/กล้องสั่น) บิตเรตจะพุ่งทะลุเกิน 35 - 58 Mbps ทำให้ไฟล์บวมโดยไม่จำเป็น ทั้งที่คะแนน VMAF ตันอยู่ที่ ~99 ไปแล้ว
2. **ทำไม 1-Pass + Lookahead ถึงพอ โดยไม่ต้องทำ 2-Pass:**
   - การเปิดพารามิเตอร์ `-look_ahead 1 -look_ahead_depth 40 -bf 4 -b_strategy 1` ช่วยให้ชิปฮาร์ดแวร์วิเคราะห์เฟรมล่วงหน้าและจัดสรรบิตเรตได้ฉลาดในรอบเดียว ได้ VMAF พุ่งขึ้นเกือบ 3 คะแนนที่บิตเรตเท่าเดิม โดยไม่ต้องเสียเวลาแปลงซ้ำรอบสอง
3. **การเลือกไฟล์ Benchmark โหด (Extreme):**
   - การนำไฟล์ยากสุด (บิตเรตเดิม 80 Mbps) มาเป็นเกณฑ์วัด ช่วยการันตีว่าค่าคอนฟิกนี้จะสามารถแปลงคลิปได้ทุกรูปแบบในโลกโดยที่ภาพจะไม่แตก

### 4. สรุปผลการทดสอบเชิงลึก: Denoise vs ExtBRC (Argon) vs Pure Peak VBR

จากการทดสอบเปรียบเทียบภาพนิ่งระดับ Micro-detail (หยดน้ำบนแว่นตาและคลื่นน้ำในสระ จากไฟล์ `GX010733.MP4` ต้นฉบับ 45 Mbps) ด้วยการขยายภาพ 2x–4x:

```
[เปรียบเทียบผลลัพธ์ทั้ง 3 รูปแบบ]
1. 20M Pure Peak VBR (สูตรหลักเดิม) : ⭐ ดีที่สุด! หยดน้ำคมใส ชัดเจนทุกเม็ด ขอบวัตถุมีมิติ ไม่มีรอยแตกบล็อก
2. 20M + Argon (-extbrc 1, -bf 4) : ⚠️ PSNR สูงขึ้น (36 dB) แต่ภาพจริงแตกเป็นบล็อกรอบแว่นตา เพราะ B-frames มากไปกับหยดน้ำ
3. 20M + Denoise (hqdn3d)          : ❌ แย่ที่สุด หยดน้ำถูกเกลี่ยละลายหายกลายเป็นคราบเบลอ ผิวสัมผัสด้าน
```

#### 📌 ข้อค้นพบสำคัญ:
1. **ทำไม B-Frames ซ้อนกัน (`-bf 4`) ถึงทำให้ภาพแตกในคลิปน้ำ:**
   - หยดน้ำที่ไหลและคลื่นน้ำเป็น Motion แบบสุ่ม (Chaotic Motion) ที่ทำนายเวกเตอร์การเคลื่อนไหวยากมาก
   - เมื่อยัด B-frames 4 เฟรม ชิป QSV จะพยายามเดาภาพจนเกิดรอยบล็อกเหลี่ยม (Macroblocking) รอบขอบแว่นตาและผิวหน้า
   - การปล่อยให้ฮาร์ดแวร์จัดโครงสร้างเฟรมตามธรรมชาติ (Default B-frame structure) ร่วมกับ Dynamic Peak Burst ให้ภาพที่ใส เนียนตา และเป็นธรรมชาติที่สุด
2. **ทำไม Denoise ถึงทำให้ภาพแย่ลงอย่างเห็นได้ชัด:**
   - เซ็นเซอร์ขนาดเล็กของ Action Cam (เช่น GoPro 1/1.9") มี High-frequency temporal noise อยู่ตามธรรมชาติ
   - อัลกอริทึม Denoise ไม่สามารถแยกความแตกต่าง ระหว่าง "Noise เม็ดทรายที่สุ่มกระพริบ" กับ "ละอองหยดน้ำขนาด 2–3 พิกเซล" ได้ จึงกวาดหยดน้ำหายไปด้วย
3. **ข้อสรุปเด็ดขาด:**
   - 🚫 **ไม่ใช้ Denoise และไม่บังคับ B-Frames/ExtBRC ลึกเกินไป**
   - ✅ **ใช้ Pure Hardware Peak VBR (20M - 25M, Preset: veryslow)** คือคำตอบที่สมบูรณ์แบบที่สุดสำหรับ GoPro บน Intel QSV UHD 710

### 5. สูตรการตั้งค่าที่แนะนำ (The True Sweet Spot ประจำเซิร์ฟเวอร์)

จากผลการทดลองเปรียบเทียบเชิงประจักษ์ (จับคู่ภาพซูมระดับพิกเซล และวัด PSNR/SSIM ข้ามหลากหลายสถานการณ์ ทั้งคลิปแสงดี, นิ่ง, และคลิปสระน้ำปราบเซียน):

| โหมดการตั้งค่าบนหน้าเว็บ | พฤติกรรมและการจัดสรรบิตเรต | ค่า PSNR ที่ได้ | ผลการประเมิน |
| :--- | :--- | :---: | :--- |
| ⭐ **QP 23 (ค่าเริ่มต้นแนะนำ - เว้นว่างช่อง Bitrate)** | **Auto-Bitrate ตามความยากของภาพ:**<br>• คลิปแสงดีทั่วไป / นิ่ง: **~8 - 10 Mbps** (ประหยัดที่ >75%)<br>• คลิปน้ำกระเซ็น / แอ็กชัน: **~23 Mbps** (คมชัดเท่าต้นฉบับ) | **37 - 40 dB** | 🏆 **ดีที่สุด สมบูรณ์แบบทุกสถานการณ์** ไม่ต้องคอยเปลี่ยนบิตเรตเอง |
| **QP 22** | • คลิปทั่วไป: **~13 Mbps**<br>• คลิปน้ำ: **~28 Mbps** | **38 - 40 dB** | ตาเปล่าแทบแยกไม่ออกกับ QP 23 แต่กินขนาดไฟล์มากกว่า ~20% |
| **Bitrate 15M (ฟิกคงที่)** | คุมขนาดไฟล์คงที่ 15 Mbps ทุกคลิป | 33.9 dB (ในคลิปน้ำ) | เหมาะกับกรณีต้องการคุมขนาดไฟล์ให้ตายตัวเป๊ะๆ |

- **ทำไมโหมด QP 23 ถึงดีกว่าการฟิก Bitrate คงที่:**
  1. ในคลิปเดินเล่น/ท่องเที่ยวทั่วไป ตัวเข้ารหัสจะลดบิตเรตลงมาเหลือเพียง 8–10 Mbps อัตโนมัติ ทำให้ได้ไฟล์ที่เล็กมากและประหยัดพื้นที่จัดเก็บ
  2. เมื่อใดที่เจอน้ำกระเด็น คลื่นซัด หรือกล้องเคลื่อนไหวเร็ว ฮาร์ดแวร์จะดันบิตเรตขึ้นไปที่ 23 Mbps ให้อัตโนมัติ เพื่อรักษาเม็ดหยดน้ำและขอบวัตถุให้คมกริบ (PSNR 37 dB)
  3. ภาพเปรียบเทียบระหว่าง QP 22 (28M) และ QP 23 (23M) พิสูจน์แล้วว่าสายตามนุษย์ไม่เห็นความแตกต่างเลยแม้แต่น้อย แต่ QP 23 ประหยัดพื้นที่ได้มากกว่า ~20%
